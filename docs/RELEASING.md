# Выпуск релиза NetPilot

Релизы публикуются в GitHub Releases (по умолчанию `iKriu/netpilot`). Устройства
проверяют подпись `SHA256SUMS` ключом ed25519, открытый ключ которого встроен в сборку.
Релиз без подписи или с подписью другим ключом не установится.

## Что нужно

- Windows, PowerShell; Go скачивается сам (`build.ps1`).
- GitHub CLI (`gh`), вход в аккаунт с правом публиковать релизы: `gh auth status`.
- JDK 17+ для интерфейса Material 3 (`web-m3`). Если `JAVA_HOME` не задан, `release.ps1`
  ищет JDK в `C:\Program Files\Java`. Без JDK можно выпустить релиз с `-SkipM3` —
  возьмётся уже собранный интерфейс из `web\static\m3`.

## Ключ подписи (один раз)

```powershell
go run ./tools/releasekey -gen
```

Создаёт пару ключей в `%USERPROFILE%\.netpilot`:

- `release.key` — закрытый ключ. Храните в тайне и **сделайте резервную копию** (менеджер
  паролей, зашифрованный носитель). Если ключ потерян, уже установленные копии
  не примут ни одного нового релиза — их придётся обновлять вручную сборкой с новым
  ключом. В репозиторий его не коммитят (`*.key` в `.gitignore`).
- `release.pub` — открытый ключ. Скопируйте его в корень репозитория и закоммитьте:
  `build.ps1` встраивает его в программу.

Другая папка: `go run ./tools/releasekey -gen -out <папка>`. Если Go не установлен,
вместо `go` используйте `.\.tools\go\bin\go.exe` (его скачивает `build.ps1`).

Без `release.pub` в корне `build.ps1` собирает программу без проверки подписи
обновлений (с предупреждением), а `release.ps1` отказывается выпускать релиз.

## Выпуск

```powershell
.\release.ps1 -Version 0.1.14 -Notes "Что изменилось"
.\release.ps1 -Version 0.1.14 -NotesFile notes.md
.\release.ps1 -Version 0.1.14 -DryRun     # только собрать и подготовить файлы
.\release.ps1 -Version 0.1.14 -KeyFile D:\keys\release.key   # ключ не в папке по умолчанию
```

Что делает скрипт:

1. Проверяет `release.pub` и закрытый ключ, доступ к репозиторию через `gh` и что релиза
   с такой версией ещё нет.
2. Собирает интерфейс Material 3 (`gradlew publishM3` → `web\static\m3`), если не указан `-SkipM3`.
3. Записывает версию в `VERSION` и собирает все платформы (`build.ps1 -Targets all`).
4. Кладёт в `dist\release` файлы `netpilot-<система>-<архитектура>`, `SHA256SUMS`
   и подпись `SHA256SUMS.sig`, затем проверяет подпись ключом `release.pub` — если ключи
   не пара, релиз не выпускается.
5. Проверяет, что Windows-сборка сообщает нужную версию (`-version`).
6. Публикует релиз `v<версия>` через `gh release create`.

Устройства увидят обновление при следующей проверке (раз в 6 часов) или по кнопке
проверки; установится оно только после нажатия «Обновить».

После выпуска закоммитьте изменённый `VERSION`.

## Проверка подписи вручную

```powershell
go run ./tools/releasekey -verify -pub release.pub dist\release\SHA256SUMS
```
